ModelEight layers, defence-in-depth. Each layer assumes the layers above it can fail. Every control lists where it is visible in the UI (screen IDs from the 225-screen pack) and the build requirement for the Java/Spring + React stack. Compliance anchors: DPDP Act 2023, CERT-In 6h breach clock (GV-09), PC-PNDT (IR-01..04), AERB (IR-05), GST (BL-19). All data below is synthetic.

7. L6 — Data protection

ControlVisible in UIBuild requirement (Java/React)

10. Threat scenarios → mitigations

Threat scenarioAttack path (synthetic example)Mitigating layers & screensResidual detection
Report-link hijack external Patient forwards / attacker intercepts a PT link SMS for #MRN-••••30 and tries to open the report. L3: OTP to registered number only (PT-01), 5-attempt lockout, 10-min OTP; L2: single-purpose audience-scoped token, exp ≤ 72h (PT-03); L1: rate limiting per link/IP; L5: no PHI in the SMS itself (NT-03); re-issue only via FO with identity check (FO-06). Failed-OTP burst alert → NT-01/GV-02; link access geo/device anomaly flag
Insider bulk export insider Billing supervisor scripts 5,000 record reads at 02:00 intending to sell referrer/patient lists. L4: purpose-of-use PAYMENT blocks report bodies; masked-by-default fields (DOC-03 §4); L5: bulk export only through governed jobs GV-15 / BL-19 / AD-12 with four-eyes DPO approval (DOC-03 §5) and watermarked output; L3: session cap; API pagination + per-principal read-rate quotas. L7 after-hours volume anomaly → GV-02 finding → AD-05 revoke; unmask-event spike on GV-16
Wrong-patient rebind safety Two patients named "R. Sharma"; tech risks acquiring under the wrong order, or a bad FO-08 merge fuses two MRNs. L5: single-MRN identity + FO-08 merge four-eyes with pre-merge snapshot; TK-01 gated worklist requires patient re-confirmation (ID + DOB) before Perform; OR-02 duplicate intercept; MWL sync TK-08 pushes patient context to the modality so no manual re-key; RD-08 pre-sign QC shows demographics against images. Unmerge runbook from snapshot; RD-15 discrepancy (diff) flow; GR intake if patient-reported
Token theft external Staff JWT/refresh token exfiltrated via malware on a counter PC; attacker replays from outside. L3: short access-token TTL (5 min) + rotating refresh tokens with reuse detection (reuse → whole session family revoked); sender-binding (DPoP/mTLS for edge and service clients); shared-terminal mode disables long-lived refresh (AU-08); step-up AU-09 required for damaging actions even with a live session; L4: scope pinned to branch — off-network replay hits IP/context checks. AU-12/AU-17 concurrent-session + impossible-travel alert; revoke ≤ 30s via AU-17
Offline queue tamper insider/physical Actor with edge-box access edits the queued offline log to alter a cash receipt amount before sync (IN-10). L8: per-entry Ed25519 signatures + monotonic sequence — any edit breaks the chain and quarantines the batch; TPM-sealed signing key not extractable; L5: idempotency keys prevent replay duplication; L6: disk encryption; BL/FO reconciliation (FO-16, BL-09, BL-18 day book) cross-checks totals against payment-gateway records (BL-04). Chain-verification failure → GV-08 incident auto-open; EOD variance flag FO-16/BL-09
Each scenario has a mapped test suite in the security regression pack (CI stage sec-regression); scenario drills scheduled on the compliance calendar GV-01 and evidenced in GV-12 DPIA.
