DOC-02

Workflow Orders — the sequence in which screens operate

Magnus HMS · MVP 1 · Architecture & Workflow Documentation
Version 1.0 July 2026 Audience: NUMINACORE development team Normative sequencing for the 225-screen pack
For each major flow: the ORDERED screen chain (build navigation and status machines to this order), the swimlane (which actor touches which screens, in order), and the state handoffs — exactly what data/status one screen must pass to the next, with the DS-03 SLA/timer that governs each hop. Where DOC-01 gives narrative scenarios, this document gives the machine: statuses, payloads, clocks.
Global sequencing rules apply to every flow below
RuleConsequence for sequencing
Safety gates evaluate at TK-01 PerformCS-01/CS-02/CS-03/CS-06 may be captured at any earlier point (ordering, check-in, pre-scan) but their satisfied/blocked verdict is re-evaluated exactly at the TK-01 → TK-02 transition. Never trust an earlier green.
Step-up AU-09 is an interstitial, not a screen in the business flowAU-09 injects before RD-09 sign, BL-06 refund, FO-09 merge commit, GV-04 execute, BL-08 high-value approve. Flows below note "(AU-09)" at the injection point.
DS-03 SLA chips are state, not decorationEvery hop that carries a timer must persist clock-start, target, and breach events; dashboards (RD-17, AD-13, GR-02, RD-11) read these, never recompute from timestamps ad hoc.
Async approvals never block the requester's screenBL-08 / AD-05 / GV-04 requests park the object in an AWAITING state and free the UI; resolution arrives by push + state change (see flows 7, 11).
Audit line everywhereEvery transition listed in a handoff table is an audit event queryable in AD-20.
Offline-first FOFlows 1–3 and the cash cycle must run against the edge node (IN-10) with queued sync; screens marked ⛅ in swimlanes are offline-capable.
