Version 1.0 July 2026 Audience: NUMINACORE development team References the 225-screen design pack (AU/PT/FO/SC/OR/CS/TK/RD/DD/BL/NT/GR/AD/IN/GV/IR/PL/DS)
Each scenario is normative: the flow chain is the exact screen order for the happy path; the step table defines what must be persisted at each hop; edge branches define the mandated behaviour when a gate fails. All data below is synthetic. Every screen carries the audit line pattern; every SLA chip follows DS-03; every sign / money / legal action requires step-up (AU-09).
Reading conventions applies to all 25 scenarios
ConventionMeaning
RED / ORANGETiered critical results: RED = referrer acknowledgement within 15 min, ORANGE = 4 h, with the escalation ladder (RD-10 → NT-01 → DD-02 → RD-11).
GateHard safety gates (CS-01 contrast, CS-02 MR, CS-03 consent, CS-06 Form F, payment state) are enforced at TK-01 "Perform" — the button is disabled until every gate is green.
Step-upAU-09 re-authentication interstitial. Required before RD-09 sign-off, BL-06 refunds, FO-09 merge commit, GV-04 deletion execution, etc.
Four-eyesIrreversible actions (merge, refund, deletion, write-off) need a second identity; asynchronous via the relevant approvals queue (BL-08, AD-05, GV-04).
