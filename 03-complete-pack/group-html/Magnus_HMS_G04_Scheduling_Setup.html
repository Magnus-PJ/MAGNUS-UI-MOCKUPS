MVP1-CORE
G4 Scheduling & Resource Setup — workspace 'Setup'
Baseline: EXTENDS · FO-S8 working hours
Purpose & workflow: The org admin defines the weekly open/close and break windows per branch; the slot-generation engine reads this grid nightly to materialise bookable slots 45 days ahead. SC-02 Holidays & closures

MVP1-CORE
G4 Scheduling & Resource Setup — workspace 'Setup'
Baseline: EXTENDS · FO-S8 holidays & closures
Purpose & workflow: The org admin maintains the closure calendar per branch: public holidays that repeat yearly and one-off closures, either whole-branch or limited to a modality. Before any closure is saved the system previews existing bookings on that date; if there are conflicts, saving spawns a bulk-reschedule task so no patient is silently dropped. Closures override working hours (SC-01) in slot generation.

SC-03 Slot templates

MVP1-CORE
G4 Scheduling & Resource Setup — workspace 'Setup'
Baseline: EXTENDS · FO-S8 slot templates
Purpose & workflow: Slot templates define how bookable time is cut per modality: slot length, patients per slot, prep gap between slots, and whether walk-ins or overbooking are allowed. Each template is versioned; the calendars that consume it are listed so an admin can see the blast radius before editing. Templates that are in use by future generated slots cannot be deleted — they are retired with an effective date instead.

G4 Scheduling & Resource Setup — workspace 'Setup'

Purpose & workflow: Per-practitioner weekly duty grids control which blocks a doctor is bookable for performing (e.g. USG) and which are reserved for reading. For radiologists the reading-vs-performing split matters: reading blocks keep report SLAs alive without consuming bookable calendar slots.

MVP1-CORE
G4 Scheduling & Resource Setup — workspace 'Setup'

Planned maintenance windows are entered here — they create a modality-scoped closure (visible in SC-02) plus reschedule tasks for any bookings caught inside the window.
