DS-14 Printing-Everywhere Pattern — Print Points, Behaviour & Failure

DESIGN SYSTEM
G17 Design System & Patterns — documentation pages
Baseline: NET-NEW · client input 26-Jul (printer access available at every location/counter)
Purpose & workflow: Every Magnus counter and room has printer access (client-confirmed), so printing is a first-class output everywhere — not an afterthought behind a browser dialog. This page defines the product-wide print contract: the registry of every printable artifact, the one print behaviour (default device per counter, silent where it should be silent, audited where it must be audited), the failure states, and the statutory print rules for invoices, Form F and reports. Paper is part of the workflow in Kerala diagnostics; the design treats it that way. Division of labour: DS-09 owns what documents LOOK like (templates, layout, letterheads); this page owns where, how and what-happens-when-it-fails.

STATE B — ONE PRINT BEHAVIOUR, PRODUCT-WIDE
Behaviour contract normative
RuleSpecification
Default device per counterEach workstation profile (AD-16 device registry) declares its default printer + paper. Routine prints (tokens, slips, receipts) go there silently — zero dialogs in the happy path. The footer shows a quiet confirmation: 🖨 Printed · FO-COUNTER-2 · 11:42.
Explicit picker, when it mattersA4 clinical/statutory artifacts (report, Form F, consent) show a one-line confirm with printer name and a change link — because wrong-tray statutory prints waste controlled forms. Preview only on request, never forced.
Duplicates & reprintsFinancial and statutory reprints render with a DUPLICATE diagonal band and reprint ordinal ("Reprint #2 of INV/NPV/26-27/0430") — the document number NEVER changes on reprint (D-16 series integrity). Reprint reasons are one tap (torn / not collected / patient request / printer failure).
AuditEvery print of PHI or a financial document is an audit event (doc_printed: who, what doc id, which device, which counter). Token/queue slips are exempt (no PHI beyond token number).
Patient-facing bilingualPatient-held artifacts (token, receipt footer, pickup slip, consent) print English + Malayalam per D-27; clinical report body remains English.
STATE C — FAILURE: PRINTER DOWN AT A BUSY COUNTER
Failure states — degrade like DS-04, never block the queue
⚠ FO-COUNTER-2 printer not responding since 11:44 IST. Tokens auto-reroute to FO-COUNTER-1 (6 m away); patients are being called by name from the board meanwhile. Receipts queue here and release on recovery. Owner: D. Nair · auto-retry every 30 s.
RuleSpecification
Reroute firstIf another registered printer exists at the branch, routine prints reroute automatically (banner states where). The workflow — registration, payment, token issue — never waits on paper.
Queue if no fallbackPrints queue per device with live count; recovery releases FIFO. Queued financial docs remain valid — the number was allocated at the business event, not at the printer.
Statutory exceptionForm F cannot be "printed later": if no printer is reachable for it, the USG cannot proceed (IR-02 blocking state) — same severity as consent refusal. This is the one artifact allowed to stop a workflow, by law.
Idempotent recoveryReleasing the queue reprints exactly the rendered artifact (stored render hash) — a recovered print is never a re-generated document. Failed-then-recovered prints do not create DUPLICATE bands.
