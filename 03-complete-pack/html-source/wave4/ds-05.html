DS-05 Empty / Loading / Error Pattern

DESIGN SYSTEM
G17 Design System & Patterns — documentation pages
Baseline: NET-NEW · empty/loading/error pattern (review §5 gap)
Purpose & workflow: In a clinical product, "nothing here" and "we couldn't load it" are safety-different statements and must never look alike. This page defines the five canonical specimens — first-run empty, filtered empty, loading skeleton, error card, and service-down page — plus the copy tone rules every module must follow. The core invariant: Magnus never shows a partial list as if it were complete.
STATE A — THE FIVE SPECIMENS
1 · First-run empty has a CTA
🗓
No appointment slots defined yet
MRI-ROOM-2 has no schedule template. Create one to start accepting bookings for this room.
Create schedule template
or copy from CT-ROOM-1
RuleSpec
StructureIcon → one-line fact → one sentence of context → exactly one primary CTA (+ optional ghost alternative). Never two primary buttons.
Only when truly emptyShown only when the unfiltered dataset has zero rows AND the load succeeded. Verified-empty, never assumed-empty.
2 · Filtered empty clear filters, no CTA
🔍
No studies match these filters
142 studies exist today; your filters (Modality: MRI · Status: unreported · Reader: Dr. V. Shetty) match none.
Clear all filters Edit filters
RuleSpec
Must differ from #1Always states the total that exists ("142 studies exist") and names the active filters, so staff never mistake a filter for an empty worklist.
Primary action"Clear all filters" — never a create-CTA; creating data is not the fix for over-filtering.
3 · Loading skeleton no spinners > 400ms
RuleSpec
400ms rule<400ms: render nothing (no flash). ≥400ms: skeleton mirroring the real layout (same row count as page size, same column widths). Bare spinners are allowed only inside buttons for in-place actions.
No layout shiftSkeleton occupies the exact final geometry; counts/KPIs skeleton as blocks, never show 0 while loading — 0 is data.
TimeoutAt 15s the skeleton must resolve to specimen 4 (error card). Skeletons never persist indefinitely.
4 · Error card no partial lists rule
⛔ Couldn't load today's unreported worklist. What failed: the RIS query timed out at 09:14 IST (request req_7f3ka9).
What we did NOT show: a partial list. 37 of 142 studies had loaded — showing them could hide a STAT study in the missing 105, so we show none.
Your work is unaffected; nothing was changed.
Retry now View cached list (as of 09:02 IST)
RuleSpec
Three statements, always(1) What failed, in task language + request ID; (2) what we did NOT show and why — the no-partial-lists rule is stated to the user, not just enforced; (3) whether any user data/state changed.
No partial listsA list either renders complete-as-of-a-timestamp or not at all. Cached fallbacks are allowed but carry cached 09:02 IST.
RetryExplicit "Retry now" button + auto-retry with backoff; never silent infinite retry that masks an outage.
5 · Service-down page (full takeover) last resort
◎ Magnus
Magnus is temporarily unavailable
Since 09:41 IST · incident INC-2026-0719 · we are on it. Drafts and offline queues on this device are safe and will sync on recovery. For STAT reads during the outage, follow the branch downtime SOP (printed copy at the front desk). Status: status.magnus.numinacore.in
Auto-reconnecting · next attempt in 28s
Rules: used only when the app shell itself cannot load (otherwise use DS-04 banners); must name the incident ID, start time (IST), data-safety statement, the paper-SOP fallback for clinical continuity, and a public status URL. Never a blank page, never a raw HTTP error.

STATE B — COPY TONE RULES
Copy tone rules — apply to every specimen above normative
RuleDo — write like thisDon't — never like this
Facts before feelings"No studies match these filters." / "The RIS query timed out at 09:14 IST.""Oops!", "Uh oh!", "Something went wrong 😕" — no interjections, no emoji in body copy, no exclamation marks.
Blame the system, not the user"We couldn't load the worklist.""You have no permission" phrasing when it's actually a load failure; "Invalid input" without naming the field and the fix.
State data-safety explicitly"Nothing was changed." / "Your draft is saved locally and intact."Silence about whether the user's work survived — in clinical software, silence reads as loss.
Task language, IDs in mono"Couldn't send the SMS reminder (DLT route)" + req_7f3ka9 for support."Error 500: upstream connect error" as the headline; stack traces or vendor names as the primary message.
Time is always absolute IST"cached as of 09:02 IST", "since 09:41 IST"."a few minutes ago", "recently" — relative time on stale clinical data is unsafe.
One next stepExactly one primary action per specimen (Create / Clear filters / Retry).Three equal-weight buttons; "Contact your administrator" as the only option when a retry would work.
Empty ≠ error, everVerified-empty says what exists ("142 studies exist today"); errors say what failed.Rendering an empty state when the fetch failed — the single most dangerous copy bug in this product.
Privacy in specimensPatient identifiers in examples/errors stay masked: "A. K•••••ni · MRD-2026-018851".Full patient names or phone numbers echoed into error cards, logs, or support IDs.
