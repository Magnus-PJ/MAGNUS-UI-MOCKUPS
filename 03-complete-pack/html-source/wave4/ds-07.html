DS-07 Masked Identity & Privacy Pattern

DESIGN SYSTEM
G17 Design System & Patterns — documentation pages
Baseline: NET-NEW · masked identity & privacy pattern (C-7)
Purpose & workflow: Canonical rules for how patient identity is masked, tokenised and revealed across every Magnus surface. Every screen that renders a patient must consume the shared <MaskedIdentity> component — never hand-roll masking. Reveal is always an explicit, reasoned, audited act; masked is the default state everywhere.
Non-negotiable principleDemographics are rendered only when the viewer's role, purpose-of-use and context all pass the policy check. Failing any one of the three yields the token form — silently, with no error state that leaks existence of the record.

STATE B — REVEAL-WITH-REASON INTERACTION SPEC
Interaction sequence component: <RevealControl>
#StepSpec
1Trigger👁 icon-button adjacent to masked field. Label on hover: “Reveal — reason required”. Keyboard: Enter on focused field.
2Purpose + reasonInline popover, not a page nav. Purpose chip is mandatory single-select; free-text reason mandatory when purpose = Support or Audit (min 15 chars).
3Step-up checkIf last identity confirmation > 15 min ago, or purpose ∉ viewer's default purposes → TOTP / passkey step-up before reveal.
4Reveal windowField unmasks for 5 minutes (session-scoped, this record only). Countdown chip shown: revealed · 4:12 left. No copy-to-clipboard on phone numbers.
5Auto re-maskOn timer expiry, tab blur > 60 s, or record close — whichever first. Re-reveal requires a fresh reason.
