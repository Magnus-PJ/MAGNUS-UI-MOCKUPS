DS-08 Form Validation & Input Patterns

DESIGN SYSTEM
G17 Design System & Patterns — documentation pages
Baseline: NET-NEW · form validation & Indian formats
Purpose & workflow: Single source of truth for validation timing, error tone and India-specific input formats across all Magnus forms. Front-office registration (FO-*), billing (BL-*) and admin screens must import these field components — local format regexes are a review-blocking defect.
STATE A — VALIDATION TIMING & ERROR TONE RULES
Validation timing rules applies to every form, no exceptions
MomentRule
On keystrokeNEVER for names, addresses, free text. Permitted only for hard input filters (digits-only in phone/PIN) and live checksum hint on GSTIN/IFSC after full length reached.
On blurDEFAULT — validate the field the user just left. Error appears under the field, focus is not stolen back.
On submitFull-form pass; render an error summary card at top listing each failed field as a link that scrolls + focuses it. Submit button stays enabled — never silently disable.
Async checksDuplicate-patient, GSTIN registry, IFSC lookup run on blur with inline spinner ≤ 2 s; on timeout, allow save with UNVERIFIED chip rather than blocking front-desk flow.
Warnings vs errorsWarnings (amber) never block submit — e.g. “age 104, please confirm”. Errors (red) block. A warning acknowledged once is not re-shown on the same visit.
Error message tone say what happened & how to fix
Message
DON'T“Invalid input.” · “Phone number wrong.” · “Error 422.”
DO“Enter a 10-digit mobile number starting 6–9, e.g. 98200 12345.”
DO“GSTIN check digit doesn't match — re-check the last character (entered …Z4, expected …Z7).”
DO“Appointment date is in the past. Pick today (25 Jul 2026) or later.”

Tone rules: no blame (“you entered”), no jargon, no exclamation marks, ≤ 2 sentences, include a valid example where format is the issue. Errors are written in the UI locale (see DS-10); field values are never auto-“corrected” silently.

Required vs optionalMark required fields with * only. Never label fields “(optional)” — anything unstarred is optional. A form where > 70% of fields are required should be re-scoped, not decorated.

Date25 Jul 2026 (DD MMM YYYY)ISO 8601 2026-07-25Display always DD MMM YYYY to kill DD/MM vs MM/DD ambiguity. Input accepts 25/07/2026, 25-7-26, “today” — echo back normalised form on blur. Timezone: IST, stored UTC with offset.
Amount ₹₹ 1,04,250.00paise integer 10425000Indian digit grouping (3 then 2s) via en-IN locale. Never float storage. Negative amounts render as − ₹ 500.00, credit notes only.
NameAs typedUnicode NFCNo keystroke validation, no “alphabet-only” regex — must accept Devanagari, apostrophes, single-word names. Only rule: non-empty, ≤ 120 chars, no leading/trailing spaces (trimmed silently).
Multi-language inputAll text fields accept any Unicode script; patient name may be captured in Latin + optional Devanagari “name as spoken” secondary field (used on hi/mr printed slips — see DS-10). Never transliterate automatically.
