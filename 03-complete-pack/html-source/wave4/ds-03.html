DS-03 SLA & Escalation Pattern

DESIGN SYSTEM
G17 Design System & Patterns — documentation pages
Baseline: NET-NEW · NS-16 SLA/escalation pattern (product-wide)
Purpose & workflow: One countdown pattern for every timed obligation in Magnus — clinical (STAT reads, critical results), operational (unmatched studies, approvals) and regulatory (DPDP data-subject requests). Every SLA surface uses the same four visual states, the same owner chip, and the same escalation ladder so staff never re-learn urgency semantics between modules. This page is normative: product teams configure the schema in Section B; they do not invent new countdown treatments.
STATE A — THE FOUR COUNTDOWN STATES
Countdown chip anatomy — the only four allowed states normative
1 · On-track (< warn threshold)
⏱ 22m left · STAT read
Teal chip. Countdown in minutes. No owner shown — the assigned queue owns it. No pulsing, no sound.
chip.teal · "⏱ {remaining} left · {sla-name}"
2 · Warning (≥ warn %, default 75%)
⏱ 7m left · STAT read Owner: Dr. V. Shetty
Amber chip. Named owner chip becomes mandatory — an SLA in warning always has one accountable human, never just a queue.
chip.amber + chip.grey owner · row gains tr.hl
3 · Breached
OVERDUE +18m · STAT read Owner: Dr. V. Shetty
Escalated 14:42 IST → Radiology lead (K. Verma) notified via DLT SMS (Jio route) + in-app.Tier-2 fires automatically; quiet hours are never applied to clinical SLAs. Escalation line is permanent — it does not clear when the item is resolved.

Word is always OVERDUE (uppercase) + elapsed overage. Actions render inline on the breached row — the user must never navigate to act.
4 · Resolved-late
Resolved · was OVERDUE +18m Closed by Dr. V. Shetty · 15:00 IST
Green chip, but the overage is retained in the label forever. Resolved-late items count against SLA attainment reports; the UI must not visually launder a late close into an on-time one.
chip.green · "Resolved · was OVERDUE +{overage}"

RuleDoDon't
One clock per obligationShow a single countdown chip per SLA per row, sourced from the server clock (IST).Never render two clocks for the same obligation, and never compute remaining time client-side from local device time.

STATE B — ESCALATION CONFIG SCHEMA
SLA definition schema — org-admin editable, versioned config contract
FieldType / defaultSemantics
sla.durationminutesFull window from trigger event to breach. Trigger event is defined per SLA (e.g. STAT read starts at study QC-complete, not at order time).
sla.warn_pctint · 75Percentage of window elapsed at which state 2 fires. Clinical SLAs may lower this (e.g. 50%) but may never raise it above 80.
sla.breach_owner_rolerole refRole that becomes accountable at breach if no individual owner exists (e.g. rad.lead, branch.manager). Resolved to a named on-duty person at fire time from the roster.
sla.tier2_delayminutes · 15Delay after breach before tier-2 escalation (next role up + SMS channel added). Tier-3 = tier-2 delay ×2, capped at org admin.
sla.channelslistIn-app always; tier-2 adds DLT SMS (Jio route); WhatsApp BSP allowed for non-clinical only. Patient-facing channels are never used for staff escalation.
sla.quiet_hoursenumnever-for-clinical Clinical class SLAs (STAT read, critical ack) hard-ignore quiet hours — this flag is read-only NONE for them in the admin UI. Operational SLAs may defer tier-2 SMS to 07:00 IST, but the in-app breach state still renders immediately.
sla.pause_ruleslistOnly allowed pause: patient-caused hold (e.g. patient left premises), recorded with reason + actor. No silent pauses; paused chips render grey "⏸ paused — {reason}".
Governance. Editing any clinical-class SLA definition requires step-up identity confirmation (TOTP/passkey) and a second approver (four-eyes) with the clinical.governance role. Config changes are versioned; live countdowns keep the definition version they started under.

Any new timed obligation added to Magnus MUST register here and inherit this pattern. A feature shipping its own bespoke countdown fails design review. Regulatory-class windows (DSR) count calendar days; operational windows count branch business hours; clinical windows count wall-clock minutes.
