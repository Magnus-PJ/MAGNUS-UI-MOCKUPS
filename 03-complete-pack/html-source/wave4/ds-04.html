DS-04 Offline / Degraded / Sync Pattern

DESIGN SYSTEM
G17 Design System & Patterns — documentation pages
Baseline: NET-NEW · offline/degraded/sync pattern (checklist #13/#14)
Purpose & workflow: Indian diagnostics branches lose connectivity routinely; Magnus degrades predictably instead of failing randomly. This page defines the three-level banner hierarchy every module must use, the action-queue contract for offline-captured work, the sync-conflict resolution modal, and the hard capability matrix that says which modules may work offline at all. The matrix is normative — report signing is NEVER offline, no exceptions.
STATE A — BANNER HIERARCHY (THREE LEVELS, NO OTHERS)
Level 1 · Offline-supported (info blue) banner.info
⬇ Working offline — this module supports it. Front-office registration continues on the branch cache. 6 actions queued locally · original timestamps preserved · will sync automatically when the link returns. Last successful sync 11:42 IST.
RuleSpecification
When shownConnection lost AND the current module is marked full or partial in the capability matrix (State C). Pinned below the topbar, non-dismissible, updates queue count live.
ToneReassuring, factual. Always states: queue count, timestamp policy, last successful sync time (IST). Never says "error".
ForbiddenNo modal takeover, no toast spam, no per-keystroke warnings. One pinned banner is the entire treatment.
Level 2 · Degraded (amber) banner.warn
⚠ Degraded — some functions paused. PACS link to CT-ROOM-1 (AE MERIDCT1) is intermittent since 12:03 IST. Worklists show the read-cache as of 12:03 IST and are marked "cached". New study arrivals may be delayed; billing runs in draft-only mode. Owner: T. Okafor (technologist on duty) · auto-retry every 60s.
RuleSpecification
When shownPartial failure: one upstream (PACS, payment gateway UPI, DLT SMS, WhatsApp BSP) is down or flapping while the app itself is reachable.
Must state(1) which dependency, (2) since when (IST), (3) exactly what is paused vs. still working, (4) a named on-duty owner, (5) retry cadence. Cached data anywhere on screen carries a cached 12:03 IST chip.
ForbiddenNever show stale data without the cached chip; never let a degraded module silently drop writes — it queues (level 1 behaviour) or blocks (level 3), nothing in between.
Level 3 · Blocked (red) banner.danger
⛔ Report signing is unavailable offline. Signing requires a live server-side identity check and hash-chain write; it cannot be queued. Your draft for study MRD-2026-018834 is saved locally and intact. Signing re-enables automatically when the connection returns — nothing to redo. Why: a queued signature could be replayed against a report edited after you last saw it.
RuleSpecification
When shownUser attempts an action marked never-offline in the capability matrix. Rendered at the point of action (replaces the primary button area), plus the pinned level-1/2 banner stays.
Must state(1) what is blocked, (2) that in-progress work is preserved, (3) that recovery is automatic, (4) one-sentence rationale ("Why:") — users obey rules they understand.
ForbiddenThe blocked action's button renders Sign report disabled — never hidden, never enabled-then-erroring.

Contract clauseSpecification
Queued timestamp preservedThe device capture time is the business timestamp forever — sync time is stored separately as synced_at. An SLA clock, a token number, an arrival time all use the capture time. The UI shows both when they differ by >5 min.
Replay orderStrict FIFO per branch per module. A conflicted item holds everything behind it that touches the same subject; unrelated subjects continue. Order is never user-reorderable.
Conflict flag⚑ amber chip, row highlighted. Conflicts never auto-resolve for clinical or financial fields; demographic no-ops (identical values) auto-merge silently and are logged.
VisibilityQueue is always inspectable (nav badge shows pending count). Nothing syncs invisibly except logged no-op merges.

Clinical-field rule (four-eyes). If any conflicting field is clinical (order, laterality, contrast flag, report content), single-user resolution is disabled: the resolver picks a value and a second qualified user (radiologist or supervisor) must confirm before the merge commits. Financial conflicts above ₹5,000 require cashier + branch manager.
Keep server valueKeep my offline value

Both versions, the choice, resolver and (where required) co-signer are stored in the conflict record — recorded in the access log.

Modal rules: shows only differing fields (never full-record diffs); derived fields render as "follows X", not as choices; "Merge both" is not offered — one side wins per field; dismissing the modal keeps the item flagged and held, it never discards either version.

STATE C — WHICH-MODULES-OFFLINE CAPABILITY MATRIX
Offline capability matrix (MVP-1) — normative, change requires clinical-governance sign-off exhaustive
ModuleOffline capabilityWhat worksWhat is blockedRationale
Front office (registration, appointments, arrivals)FULLRegister, book, reschedule, mark arrived — all queue with preserved timestamps.Cross-branch lookups (cached list only, marked cached).Patient flow must never stop for connectivity; identity dedup runs at sync.
Billing & paymentsDRAFT-ONLYDraft invoices, estimates, discount capture pending approval.Finalising invoices, UPI collection (payment gateway UPI requires live confirmation), refunds, receipt numbering.Fiscal document numbers and payment confirmations must be single-sourced server-side; duplicates are a statutory problem.
RIS worklistsREAD-CACHEView worklist/study status as of last sync, always chip-marked cached 12:03 IST.Status transitions, reassignment, priority changes.Two branches mutating one worklist offline creates unsafe double-work; reading stale is safe if labelled.
Report draftingFULL (local drafts)Dictate/type draft, templates, macros — saved to encrypted local store.Assigning drafts to other readers.Drafting is single-author; no shared state to corrupt.
Report signingNEVER—Sign, amend-and-resign, addendum sign.Signature = live step-up identity check + server hash-chain append at sign time. A queued signature could be replayed against content changed after the signer last saw it, and the signature timestamp would be unverifiable. No cached credential is ever acceptable. This row cannot be reconfigured per-tenant.
Critical results / STAT commsNEVER—Critical notify, ack recording.An unsent "sent" state is a patient-safety lie; the pattern requires live delivery receipts (DLT SMS / WhatsApp BSP).
Admin, config, user managementNEVER—All writes.Config drift across branches during a partition is unrecoverable by FIFO replay.
Legend: FULL queue-and-sync · DRAFT-ONLY / READ-CACHE partial with explicit limits · NEVER hard-blocked with level-3 banner. Any new module must declare its row here before build; "we'll decide offline behaviour later" fails design review.
Implementation noteFrontend: global ConnectionStatusProvider (React); offline actions queue in IndexedDB with client-generated correlation IDs and replay on reconnect. Backend edge service exposes IDEMPOTENT sync endpoints (correlation-ID dedupe). Offline registrations use temporary local UUIDs; the canonical MRN is assigned at sync; collisions route to the merge queue (FO-08).

Design-system pages are versioned artefacts (DS-04 v1.2, updated 21 Jul 2026 IST by K. Verma). Offline queue replays, conflict resolutions and capability-matrix changes are written to the immutable audit trail and recorded in the access log.
