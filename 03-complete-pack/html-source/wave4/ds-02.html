Banners — five intents
InfoContext the user should know; no action required. Example: mirror-sync explanation on metering.
WarningAction needed soon; service still working. Example: SMS overage under soft-cap policy.
DangerBreach, destructive context or active privileged session. Persistent while the condition holds — never auto-dismisses.
SuccessCompleted operation with durable evidence (ids, timestamps). Prefer inline over toast for auditability.
RegulatoryCompliance/privacy framing: DPDP notices, retention rules, zero-standing-access attestations, metering accuracy.
Rules: one banner intent per condition; max two banners stacked before content; banner b line states the fact, body states the consequence and next step.

Primary (teal)Exactly one per view — the single most likely correct action. Two primaries on one screen is an automatic review failure.

GhostTertiary navigation-like actions inside cards/tables.
DisabledOnly when the enabling condition is stated nearby (e.g. "Complete step-up to enable"). Never disable without telling why.
