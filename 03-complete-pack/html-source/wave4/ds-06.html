DS-06 Audit & Step-up Pattern

DESIGN SYSTEM
G17 Design System & Patterns — documentation pages
Baseline: NET-NEW · audit & step-up pattern
Purpose & workflow: Magnus is privacy-first under DPDP: every consequential screen tells the user, in one 🔒 footer line, exactly what is being recorded about their presence there — and every sensitive action re-proves identity before it executes. This page defines the audit footer phrasing per action class, the audit event schema, the step-up modal and its action matrix format, and the hash-chain / tamper-evident chips that make the trail verifiable.

✓ Tamper-evident · sha256:4bc1…9e
On each audit event detail: this event's hash re-verified against its neighbours at render time. Copy rule: say "tamper-evident", never "tamper-proof" — we detect, we don't claim to prevent.

A failed row renders with content struck through and its neighbours flagged; the record is still shown (evidence), never silently hidden.

The step-up method, factor age and result are attached to the signing event and recorded in the access log.

Modal ruleSpecification
Names the exact actionTitle and body restate the specific action + masked subject ("signing report MRD-2026-018834"), never generic "Confirm your identity". What is confirmed is what executes — the payload is bound to the challenge.
Factor rulesPasskey preferred, TOTP fallback, backup codes accepted-and-voided. Password re-entry alone is never a valid step-up. Patient OTP realm factors can never satisfy a staff-realm step-up.
Freshness windowGrade A actions: fresh challenge every time. Grade B: a step-up ≤10 min old may be reused, shown as "verified 14:41 IST · reuse". Window is org-configurable 5–15 min, never longer.
Failure / cancel3 failed attempts locks step-up 5 min and notifies the user's other channel; cancel = no action, no partial state, logged as declined challenge.
Four-eyes compositionWhen dual-control applies, the second approver completes their own step-up on their own session — one person on two devices is blocked by same-user + same-device checks.

Format rules: every module's spec ships this exact six-column matrix covering all its actions; grades are only A (fresh step-up), B (reusable window), C (none). An action absent from the matrix defaults to grade A until classified — the safe default is friction.
