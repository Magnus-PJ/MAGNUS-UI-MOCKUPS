Deep-link & breadcrumb rules
RuleSpec
URL shape/w/<workspace>/<group>/<screen>/<entity-id>
e.g. /w/andheri-west/rd/worklist/V-260725-0412
No PHI in URLsEntity IDs only (visit, order, token) — never name, phone or MRN fragments; URLs land in browser history and proxy logs (DS-07).
Breadcrumb depthMax 3 levels: Workspace › Group › Screen. Entity context renders in the page title, not a 4th crumb. Crumbs are the route truth — no “fake” crumbs from arrival path.
Auth on deep linkUnauthenticated hit → AU-01 with realm inferred from workspace, then return to the exact link. Step-up-gated screens (PV-*, refunds) re-challenge even inside a live session.
Branch switchDeep link into another permitted branch prompts an explicit switch banner — never silently changes the active branch context.
Dead linksMerged/voided entities redirect to the survivor with an info banner (“Visit merged into V-260725-0398”), preserving the audit trail.

Denied deep-link attempts, branch context switches and cross-realm navigation events are recorded in the access log.
